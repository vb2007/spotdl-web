# v45 — Internationalization (Hungarian + English)

Branch: `dev-i18n` → PR into `main`
Version: `4.45.0`

## Scope

Every user-visible string in the frontend is hard-coded English today. Most of the app's users are
Hungarian. This version adds **full i18n coverage for Hungarian (`hu`) and English (`en`)**:

- the language is **auto-detected** from the user's environment;
- an explicit **language switch** overrides it, and is stored per user.

It's placed after every UI slice (v39–v44), so it translates the final strings, including v44's
shortcut help overlay. It comes before polish (v46), so polish lays out against real Hungarian
strings, which run noticeably longer than English ones.

## Design

- **Library:** **Paraglide JS** (inlang), the SvelteKit-recommended option. It compiles messages to
  tree-shaken, typed functions, needs no runtime loader, and works with `adapter-static`. If
  implementation finds a concrete blocker, `svelte-i18n` is the fallback, and the reason goes in
  GOTCHAS. Messages live in `frontend/messages/en.json` and `hu.json`. Keys are stable and
  descriptive, never the English text.
- **Locale resolution, in priority order:**
  1. **The user's saved preference**, stored server-side on the `users` row or the existing
     per-user settings (the same place v44's shortcut toggle lives). Owner-scoped, and it follows
     the user across devices.
  2. **Before login** (or when there's no saved preference): a `localStorage` choice made on
     `/login` (wrapped in try/catch).
  3. **Auto-detect:** the first of `navigator.languages` whose primary subtag is `hu` or `en`.
  4. **Fallback:** `en`.

  The resolved locale sets `<html lang>` and updates it on switch, without a full reload if the
  library allows.
- **The language switch:** on `/account` (persisted), with a compact equivalent on `/login` (local
  only, adopted into the profile on first login if the profile has none). Each language is labelled
  in its own name ("Magyar" / "English"). Designed through the **impeccable skill** in the v40–v42
  system.
- **Coverage, all of it:**
  - every route and component string;
  - `aria-label`s, `title`s and `alt` text;
  - `<svelte:head>` titles;
  - empty, loading and error states;
  - confirmation dialogs (v42);
  - the keyboard help overlay and its key descriptions (v44);
  - stats page labels and chart text alternatives (v43);
  - state labels (`STATE_LABEL`, `ATTEMPT_OUTCOME_LABEL`, the job rollup labels).
- **The signal-receiver voice.** Labels like "receiving", "fading — waiting" and "no signal — not
  found" are a deliberate product voice (DESIGN.md §1). Translate the *voice*, not word for word.
  Use impeccable's `clarify` for the Hungarian copy. **The owner reviews the Hungarian strings** in
  the PR, so list them in a review-friendly table.
- **Formatting via `Intl`**, with the active locale: dates and times (attempt timestamps, the
  countdown), relative times, numbers, file sizes, durations. Hungarian puts the noun in the
  singular after a numeral ("5 szám", not "5 számok"), so use the library's plural support or
  `Intl.PluralRules`. Never concatenate number and noun in code.
- **Backend messages.**
  - The frontend often shows `ApiError.message`, the backend's `detail` string. User-facing API
    errors gain a stable machine **`code`** alongside the English `detail` (an additive response
    field). The frontend translates by `code` and falls back to the raw `detail` when the code is
    unknown.
  - Inventory every `HTTPException` the UI can surface, and give each a code. Don't translate on
    the server: the backend stays language-neutral.
- **Out of the translation path, on purpose:**
  - track, artist and album metadata, raw error text inside attempt history (monitoring needs the
    original), and proxy labels;
  - Matrix alerts (admin, English);
  - logs.
- **Check for missing translations.** The build (or a lint script) fails if `hu.json` and
  `en.json` key sets differ.

## Out of scope

- Languages beyond `hu`/`en`.
- Translating backend logs, Matrix alerts or track metadata.
- URL-prefixed locale routes (`/hu/...`). The app is behind login and isn't indexed, so locale is a
  user setting, not a route. This also avoids new nginx `location` blocks.

      removed (shown once, then restored).
